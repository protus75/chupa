When a stage raises an exception it does not return as an outcome (for example a GitError while lifting the ticket plane, or an OSError), `run` leaves the stem journaled `running` with no terminal transition and exits with a raw Python traceback instead of exit 2. Reconcile-on-entry already reaps the orphaned run. The only part still missing is mapping an unexpected exception to exit 2.

Existing registry records already cover both parts of this note. Record 000097 covers mapping exceptions that escape `main` (GitError, OSError and others) from a traceback with exit 1 to exit 2 or a crash path; that is the part this note says is still unbuilt. Record 000098 covers a stem left in `running` after the stage seam raises; this note itself says reconcile-on-entry now reaps that orphan. The note adds no new harmful behavior beyond what 000097 already declined.

- declined-box-000097-cd50f4c0: unexpected exceptions such as GitError and OSError escape `main` as a traceback with exit 1, and the record proposes mapping them to exit 2
- declined-box-000098-2dcb343f: when the stage seam raises after `to: running`, the stem is left without a terminal transition until reconcile-on-entry reaps it
- The message itself says reconcile-on-entry reaps the orphan and only the mapping from traceback to exit 2 is still unbuilt
