A retro finding from drain-ceiling-carried-on-handoff: requisition review approved a bug ticket twice even though its `## Regression` command was a bare `./dev.py test ... -k deadline`. That command can never print the single `regression_result` JSON object that the bug_evidence gate decodes, and its reproducer was neither carried nor fenced. The finding asks the requisition review spec to snag both defects.

The merged ticket requisition-review-regression-protocol-snag already made this change. Line 28 of `chupa/specs/requisition_review.md` now requires a Regression command to run a reproducer that sits under both a `- carries:` test or fixture prefix and a `## Scope fence` prefix. The reproducer must print only one JSON object keyed `regression_result`, and runner output on stdout from `./dev.py test` or pytest is a snag. The only part of the proposal not covered is the `-k` selector criterion. That part is moot, because a bare selector command is already a snag. Reopen if a requisition review approves a Regression command that prints runner output or uses an unfenced, uncarried reproducer after this spec line merged.
