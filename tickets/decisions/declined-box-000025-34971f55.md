`chupa/config.py` `load_config` reads the config file with `Path.read_text` directly, not through the FileSystem seam, because the seam has no read verb. The note proposes adding a read verb only when a fake-driven config test needs one. The config rewrite in `migrate-config` already goes through the seam's write and replace.

This is a seam-consistency and test-convenience note, not a runtime gap. Reading the config file directly gives the same result as reading it through a seam verb, and nothing shows wrong behavior or a test that cannot be written. The note itself makes the change depend on a future need. Decision box-000017 settled the same pattern for the lockfile's raw os/fcntl calls. Reopen if a config test needs to fake file reads and cannot, or if the direct read causes wrong runtime behavior.
