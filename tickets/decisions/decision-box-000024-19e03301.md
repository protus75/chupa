Relative config paths use two different bases. `state_dir`, `worktree_root` and `report_inbox` resolve against the directory that holds the config file, while `rules_doc` and `context_files` resolve against the checkout. The spec section on config never says which base applies, so the note asks for it to be written down.

This is a gap in what the spec says, not a runtime defect. The note reports the loader's behavior without calling it wrong, and gives no case where a relative path pointed to the wrong place. Writing down the bases would be a documentation change with no runtime effect, so it does not meet the bar for authoring a ticket. It resembles decision-box-000022-a109febf, another case where the config loader decides something the spec leaves out, but it is about a different fact, so it is not a duplicate.

- The message is a bootstrap-ingest suggestion that only describes how relative paths currently resolve. It names no failure.
- No open ticket, merged stem or decision covers which base relative config paths use.
