A bootstrap note said `chupa/seams.py` began as signature-only Protocols and that git.py would add the real process-exec contract later. It also pointed out that `journal.py` types its clock parameter as a raw `Callable` instead of `seams.Clock`. The process-exec contract now exists, and the clock annotation is only a type-name difference.

The first part of the note has already been done: `seams.py` now has `SubprocessExec` with `start_new_session` process groups, `GroupExec.kill_group` using `os.killpg`, and `ExecutableNotFound`, which makes a missing executable fail closed. The remaining point is that `journal.py` line 145 types its clock as `Callable[[], datetime]`. That is the same type as `seams.Clock` (`seams.py` line 14 defines `Clock = Callable[[], datetime]`), and the clock is still injected through the constructor, so runtime behavior does not change. Using the alias instead would be a style cleanup, not a fix for something that goes wrong when the code runs.
